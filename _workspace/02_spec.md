# 사이트핏 전체 제품 스펙

## 목적
사이트핏은 다양한 업종의 홈페이지가 검색엔진, AI 답변엔진, 고객에게 이해되기 어려운 지점을 진단하고, 그 결과를 상담, 견적, 개발/콘텐츠/마케팅 개선 작업, 재진단, 월간 관리로 전환하는 플랫폼입니다.

## 핵심 원칙
- 일반 SEO 점수 도구가 아닙니다.
- AI가 고객 사이트를 자동 수정하는 서비스가 아닙니다.
- 유료 리포트 판매가 1차 목표인 SaaS가 아닙니다.
- 핵심은 다양한 업종의 개선 수요를 발견하고 실행 상담과 견적으로 연결하는 진단형 영업 접점입니다.
- 고객에게 노출되는 문구는 한글을 기본으로 사용합니다.
- 공개 첫 진단은 URL만 입력받습니다.
- 무료/유료 여부와 상관없이 진단 결과는 모두 보여줍니다.
- URL 기반으로 업종 카테고리를 추정하되, 추정값은 상담 단계에서 보정할 수 있습니다.

## 고객 흐름
1. 고객은 공개 진단 화면에서 사이트 URL만 입력합니다.
2. 업종과 현재 목표는 초기 진단 전에 묻지 않습니다.
3. 플랫폼은 입력 URL을 안전하게 검증하고 제한 범위 안에서 크롤링합니다.
4. 기술 SEO, 검색이해도, AEO, GEO, 전환 구조를 룰 기반으로 진단합니다.
5. AI mock은 외부 AI API 연동 전까지 구조화된 실제 진단 근거를 한글 요약과 작업지시서 문장으로 변환합니다.
6. 고객은 전체 진단 결과, 전체 실제 분석 이슈, 예상 작업 범위, 공유 리포트 링크를 확인합니다.
7. 상담 신청 단계에서 이름, 이메일, 사이트 URL, 예산, 희망 작업, 희망 일정을 받습니다.
8. 운영자는 리드와 진단 결과를 확인하고 상담, 견적, 계약, 개선 작업으로 진행합니다.
9. 개선 후 재진단하고 월간 관리로 전환합니다.

## 전체 진단 결과 공개 정책
- 사이트핏은 리포트 판매형 상품이 아니라 개발/SI 영업 전환 접점입니다.
- 따라서 무료/유료 여부와 상관없이 진단에서 확인한 주요 개선 유형과 작업지시서를 모두 보여줍니다.
- 정보 제한으로 유료 전환을 유도하지 않고, 실제 문제와 작업 범위를 충분히 보여준 뒤 상담과 견적으로 전환합니다.
- 원시 탐지 건수는 페이지별 탐지로 유지하고, 고객 화면에는 중복 이슈를 묶은 전체 개선 유형을 표시합니다.

## 진단 레이어
- 기술 SEO: 접근성, robots.txt, sitemap.xml, canonical, title/meta, robots meta, lang, viewport, JSON-LD 유효성, 구조화 데이터 가능성, 이미지 alt, 이미지 크기 속성, 링크 앵커.
- 검색이해도: title/H1/본문 주제 일치, 서비스/제품/지역/업종 표현, 본문 정보량, H1/H2/H3 제목 계층, 내부 링크, CTA.
- AEO 준비도: FAQ, 질문형 제목, 질문 아래 직접 답변, FAQPage schema, 가격/견적 기준, 절차, 비교 콘텐츠.
- GEO 준비도: 브랜드 엔티티, Organization/LocalBusiness schema, sameAs, 차별점, 신뢰 근거, 인용 가능한 문장, 외부 신뢰 출처 링크.
- 전환 구조: 상담/문의/견적/전화/구매 CTA, 실제 연락 수단, 폼 접근성, 신뢰 요소, 모바일 전환.

## 강화된 분석 항목
- 업종 카테고리 추정: 병원/의료, 법률/전문자문, 교육/학원, 쇼핑몰/커머스, 제조/산업, IT/소프트웨어, 금융/보험, 부동산/건설, 식음료/외식, 뷰티/미용, 여행/숙박, 콘텐츠/미디어, 공공/비영리, B2B 서비스, 일반 기업.
- 페이지 유형 분류: home, service, product, portfolio, article, contact, legal, general.
- 페이지 메타데이터 추출: title, meta description, H1, canonical, robots meta, schema 타입, 이미지 수, alt/크기 속성 누락 수, lazy 이미지 수, H1~H6 개수, heading 계층 오류, 본문 단어 수, OG 메타, viewport/lang/charset, 내부/외부 링크 수, 빈 앵커 수, 폼/연락 신호.
- 사이트 단위 중복 탐지: 중복 title, 중복 meta description, 중복 H1.
- 내부 링크 그래프 기초 분석: 내부링크 고립 페이지 탐지.
- 내부 링크 수집 점검: 크롤링된 페이지에서 발견됐지만 수집 결과에 포함되지 않은 내부 URL 확인.
- 사이트 페이지 커버리지 탐지: 문의 페이지, 신뢰/정책 페이지, 핵심 상품/서비스 페이지 구조 누락 확인.
- schema 타입 추출: Organization, Service, Product, FAQ 등 JSON-LD `@type` 확인.
- JSON-LD 형식 오류 탐지: 파싱되지 않는 schema 스크립트 수 확인.
- AEO 구조 분석: 질문형 H2/H3 개수, 질문 아래 직접 답변 문단 수, FAQPage schema 적용 여부 확인.
- GEO 엔티티 분석: Organization/LocalBusiness schema, sameAs, 브랜드 정의형 문장, 인용 가능한 수치/기준/수행 이력 문장, 외부 신뢰 출처 링크 확인.

## 리포트 구조
- 대표용 요약
- 종합 준비도 점수
- 주요 개선 유형 전체 목록
- 페이지별 탐지 건수
- 작업 범위 요약
- 분석 근거 요약: 페이지별 유형, title, H1/H2 개수, 본문량, 질문형 제목/직접 답변 수, FAQ schema, 엔티티 schema, 인용 문장, 외부 신뢰 링크, 내부/외부 링크 수, 빈 앵커, schema, 이미지 alt/크기 속성, viewport, robots 상태.
- 개발자용 작업지시서 전체 목록
- 규제 업종 주의 문구
- 성과 보장 금지 문구
- 상담 CTA
- 공유 토큰 기반 리포트 링크

## 상담 신청 필수 정보
- 이름
- 이메일
- 사이트 URL
- 예산 범위
- 희망 작업
- 희망 일정

예산 정보는 리드 등급 분류에 필수입니다.

## 현재 구현 상태
- Node.js 내장 모듈 기반 서버와 정적 UI.
- JSON 파일 저장소.
- 한글 공개 진단 화면, 관리자 화면, 리포트 화면.
- URL-only 공개 진단 폼.
- 실제 크롤링/룰 기반 진단 결과.
- 중복 이슈를 묶은 전체 개선 유형 공개.
- 페이지 유형/메타데이터/고급 기술 신호/사이트 단위 중복/고립 페이지/페이지 커버리지 분석.
- 링크 상태 진단: 크롤링된 페이지의 내부/외부 링크를 제한 수량 안에서 점검하고 4xx, 5xx, 리다이렉트 링크를 이슈화.
- 업종별 보강 규칙: URL 분석 결과로 추정한 카테고리에 따라 쇼핑몰 구매정보, 제조 상세정보, 교육 과정정보, B2B 의사결정 자료, 규제 업종 표현 리스크를 별도 점검.
- 성능 기초 진단: 정적 HTML 기준으로 렌더 차단 가능 CSS, defer/async 없는 동기 script, lazy loading 미적용 이미지를 점검.
- JS 렌더링 사이트 분석: SPA shell로 보이는 HTML은 선택적 렌더러를 통해 렌더링 후 HTML, 링크, 성능 지표를 수집할 수 있습니다. Playwright 어댑터는 선택 모듈로 분리되어 있고, 기본 운영은 기존 HTML 크롤링을 유지합니다.
- 성능 심화 진단: 렌더러가 제공한 LCP, CLS, Total Blocking Time, 리소스 수, 전체 전송량, 이미지 전송량을 진단 이슈와 리포트 근거에 반영합니다.
- 관리자 영업 UI: 리드 목록 중심 화면을 영업 파이프라인 보드, 상담 이력, 견적 상태, 재진단 히스토리, 운영 리소스 요약 중심으로 확장했습니다.
- 공개 결과 화면과 공유 리포트의 분석 근거 요약에 성능 통계까지 노출.
- chat mock AI 경계.
- 자동 테스트 기반 검증.
