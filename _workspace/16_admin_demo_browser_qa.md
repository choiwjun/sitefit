# 관리자 데모 플로우 브라우저 QA

작성일: 2026-05-02

## 목적

관리자 화면의 데모 생성 UX가 실제 브라우저에서 동작하는지 확인했다. Playwright 패키지는 설치되어 있지 않아, 설치된 Chrome을 headless로 실행하고 Chrome DevTools Protocol로 DOM과 네트워크 결과를 검증했다.

## 검증 대상

- URL: `http://127.0.0.1:3000/admin.html`
- 시나리오:
  1. 관리자 화면 로드
  2. 데모 fixture 목록 로드 확인
  3. `commerce` 데모 선택
  4. 데모 생성 폼 제출
  5. 생성 결과 카드 확인
  6. `데모만` 필터 자동 전환 확인
  7. 진단 기록의 `Demo` 배지 확인
  8. 생성된 리포트 링크가 200으로 열리는지 확인

## 결과

통과.

검증값:

- fixture 옵션 수: 5
- 데모 실행 패널 존재: true
- 데모 생성 후 리포트 링크 존재: true
- 자동 필터 값: `demo`
- 파이프라인 카드 수: 1
- 진단 기록 row 수: 1
- Demo 배지 수: 1
- 리포트 링크 HTTP 상태: 200

생성 예시:

- run: `run_1777695859774_2g8tlu`
- lead: `lead_1777695860828_zvh258`
- estimate: `estimate_1777695860840_a5dg7g`

## 참고

브라우저 QA 과정에서 로컬 데이터 저장소에 데모 run, lead, estimate가 실제로 1세트 생성되었다. 이는 관리자 데모 생성 기능의 정상 동작 검증을 위한 데이터이며, 운영 데이터 삭제 기능은 아직 구현하지 않았다.

## 다음 권장 작업

현재 흐름은 시연 가능하다. 다음은 로컬/운영 데이터가 섞이지 않도록 데모 데이터 삭제 API를 만들지, 아니면 필터만 유지할지 결정하는 단계다. 삭제 API는 데이터 손실 위험이 있어 별도 확인 후 진행하는 편이 맞다.
