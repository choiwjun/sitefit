# QA 보고서

## 자동 테스트 실행 명령

```powershell
npm test
```

## 검증 범위
- 공개 HTTP/HTTPS URL 허용 및 localhost, 사설망, 링크 로컬, 미지원 프로토콜 차단.
- DNS 해석 결과가 내부망인 공개 호스트 차단.
- 제한 크롤링의 페이지 수, 깊이, byte, query parameter, robots disallow 제한.
- sitemap URL 추출, sitemap index 추적, sitemap 기반 크롤링 seed 적용.
- 기술 SEO, 검색이해도, AEO, GEO, 전환 구조 이슈 카드 생성.
- 메타, FAQ, 신뢰 근거, 구조화 데이터, CTA가 있는 페이지의 점수 보상.
- 가격/견적 기준, 서비스 절차, 비교 콘텐츠, 차별점 근거 부족 감지.
- 리드 점수화와 상담 필수 필드 검증.
- 영업 상태 전이, 견적 초안 생성, 견적 상태 전이 검증.
- 재진단 전후 비교.
- 파트너 배정, 월간 관리 계정, 운영 메모, 관리자 운영 API.
- JSON 저장소 export/import.
- 관리자 토큰 보호, 관리자 세션 쿠키, 잘못된 토큰 거절.
- 공유 토큰 기반 리포트 접근 제어.
- 실제 진단 이슈명과 점수를 반영한 한글 AI 보조 리포트 생성과 금지 표현 방지.
- 규제 업종 표현 주의 문구.
- 저장된 진단 리포트 JSON/HTML 제공.
- 공개 진단 폼이 URL만 받는지 검증.
- 공개 결과 화면이 실제 분석 이슈와 작업 범위 요약을 표시하도록 JS 문법 검증.
- 링크 상태 진단이 깨진 링크, 서버 오류 링크, 리다이렉트 링크를 구분하고 안전하지 않은 링크와 중복 링크를 건너뛰는지 검증.
- 추정 업종 기반 보강 룰이 커머스, 의료/법률/금융, 제조 등 업종별 이슈를 생성하는지 검증.
- 성능 기초 진단이 렌더 차단 가능 CSS, 동기 script, lazy 미적용 이미지를 감지하고 공개 결과/공유 리포트 근거 요약에 노출되는지 검증.
- JS 렌더링 크롤러가 sparse SPA shell을 렌더링 HTML로 대체하고 렌더링 후 링크를 후속 크롤링에 사용하는지 검증.
- 렌더링 성능 지표 LCP, CLS, Total Blocking Time, 전체 전송량, 이미지 전송량이 진단 이슈로 생성되는지 검증.
- 관리자 화면에 영업 파이프라인, 상담 이력, 견적 상태, 재진단 히스토리 업무 영역이 노출되는지 검증.
- 공개 진단 결과가 핵심 요약, 우선 개선 항목, 진단 영역별 결과, 페이지별 분석 근거 요약, 전체 이슈 펼쳐보기 구조로 그룹화되는지 검증.
- 기본 크롤 범위가 50페이지, 링크 점검 기본 상한이 100개로 설정되는지 검증.
- 진단 결과 JSON, 공개 결과 화면, 공유 리포트가 분석률, 수집 제외, 링크 점검, JS 렌더링 지표를 노출하는지 검증.
- 폼 입력 라벨 누락, 버튼 접근성 이름 누락, HTTPS 혼합 콘텐츠, 리다이렉트 체인 과다 이슈를 검증.
- 문자 인코딩 선언 누락, 중복 id, 안전하지 않은 form action, iframe title 누락 이슈를 검증.
- 현재 진단 근거 기반 웹 품질 점수(`성능`, `접근성`, `보안 관행`, `SEO`) 산출과 공개/공유 리포트 노출을 검증.
- quoted/unquoted/boolean/mixed-case HTML 속성 파싱과 unquoted meta, viewport, canonical, image alt/size/lazy, aria-label 추출을 검증.
- `/health` 배포 헬스 체크.

## 수동 테스트 로컬 서버 실행

```powershell
$env:PORT = '3001'
npm start
```

확인:

```powershell
curl.exe -s http://localhost:3001/health
curl.exe -s -I http://localhost:3001/
curl.exe -s -I http://localhost:3001/admin.html
```

## 잔여 리스크
- 실제 외부 URL 진단은 대상 사이트 가용성과 네트워크 상태에 영향을 받습니다.
- 크롤 범위가 50페이지로 늘어나 실제 외부 진단 소요 시간이 증가할 수 있으므로 운영 rate limit과 큐 분리가 필요합니다.
- 관리자 화면은 리드, 진단, 견적의 핵심 상태 변경을 지원하지만 전체 영업 워크플로 편집 UI는 계속 확장해야 합니다.
- 관리자 API는 `ADMIN_TOKEN` 보호를 지원하지만 운영용 사용자 권한 체계는 아직 없습니다.
- 현재 저장소는 JSON 파일 기반이므로 운영 DB 전환이 필요합니다.
