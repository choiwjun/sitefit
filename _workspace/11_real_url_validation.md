# 실제 URL 기반 진단 품질 검증

작성일: 2026-05-02

## 목적

무료 진단 플랫폼 대비 영업에 필요한 신뢰도를 확인하기 위해 실제 공개 사이트 5개를 SiteFit 엔진으로 진단했다. AI API나 PageSpeed API 없이 현재 수집 HTML, 링크, 렌더링, 업종 룰만으로 어느 정도 실행 가능한 인사이트가 나오는지 확인했다.

## 검증 조건

- 로컬 서버: `http://127.0.0.1:3001`
- 공통 옵션: `maxPages=5`, `maxDepth=1`, `maxLinkChecks=20`
- Bosch는 응답 안정성을 위해 `maxPages=3`, `maxLinkChecks=10`
- 외부 사이트 특성상 응답 차단, 리다이렉트, 대형 사이트 URL 수에 따라 분석률은 낮게 보일 수 있다.

## 확인된 강점

- 실제 URL에서도 기술 SEO, 전환 구조, AEO/GEO 콘텐츠, 링크 점검, 렌더링 기반 지표가 함께 나온다.
- 업종별 룰은 의료, 교육, 커머스, 제조처럼 다른 구매 판단 기준을 분리해서 이슈를 만든다.
- 추천 패키지와 상담 포인트가 연결되어 “무료 진단 결과 -> 견적 상담” 흐름으로 전환하기 좋다.

## 발견한 리스크

1. 대형 사이트 분석률이 2~8%로 표시되어 엔진이 약해 보일 수 있다.
   - 원인은 엔진 성능 부족이라기보다 `maxPages` 표본 진단에서 발견 URL 전체를 분모로 쓰기 때문이다.
   - 보완: `수집 한도 사용률`, `표본 진단 여부`, `수집 제외 사유 카운트`를 추가했다.

2. 커머스 홈/개요 페이지에서 `가격 또는 견적 기준 부족`이 과탐지될 수 있었다.
   - 상품 가격은 제품 상세나 컬렉션 페이지에 있는 경우가 많다.
   - 보완: 커머스 `home/general/portfolio/article` 페이지에서는 일반 가격/절차/비교 누락 룰을 완화하고, 커머스 구매 정보 룰은 업종 룰에서 유지한다.

3. 제조 사이트에서 사용자가 업종을 지정해도 상담 멘트가 탐지 카테고리만 따라가면 “일반 기업”처럼 약하게 보일 수 있었다.
   - 보완: 상담 전환 문구는 사용자가 선택한 업종을 우선 반영하도록 조정했다.

## 이번 조정

- `analysisCoverage.crawlBudgetUsageRate` 추가
- `analysisCoverage.isSampledCrawl` 추가
- `analysisCoverage.skippedReasonCounts` 추가
- 공개 리포트와 HTML 리포트에 `수집 한도 사용` 지표 노출
- 신뢰 근거 카드에 표본 진단 여부를 반영
- 커머스 홈/개요 페이지 일반 가격 과탐지 완화
- 상담 전환 트랙의 업종 라벨 우선순위 보정

## 판정

현재 엔진은 “무료 진단 대비 분석량이 많다”는 포지션을 만들 수 있다. 다만 대형 사이트에서는 분석률만 보여주면 역효과가 있으므로, 영업 화면에서는 반드시 `분석률`과 `수집 한도 사용률`을 같이 보여줘야 한다.

다음 권장 작업은 실제 URL 샘플을 고정한 회귀 검증 세트를 만드는 것이다. 네트워크 상태에 따라 외부 사이트 결과가 흔들리므로, 영업 데모용으로는 대표 HTML 스냅샷 기반 fixture를 추가하는 편이 안정적이다.
